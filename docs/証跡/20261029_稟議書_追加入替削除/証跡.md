# 稟議書の追加・入れ替え・削除（発注依頼一覧）証跡 2026-10-29

## 対象
- PC版（akioka-web-application-pc）`Stock/OrderRequests` の発注依頼詳細 → 稟議書ファイル
- 物品システム（akioka-cloud-iot-legacy）`/api/order_request/upload_file` のファイル名変更

## 修正前の問題
- 2件目以降の稟議書をアップロードすると500エラー（`file_path_sub` が文字列のまま `in_array()` に渡り TypeError）→ 実質「1件しか添付できない」
- 「既存」（`file_path`）のファイルは削除できない
- 同じ秒に複数アップロードするとファイル名が衝突し上書き
- 物品システムのURLが本番固定で、ローカルから試すと本番DB・本番ファイルに書き込まれる

## 検証環境（本番には一切接続していない）
- 物品システム：127.0.0.1:8019（ローカルDB `akioka_db`）
- PC版：127.0.0.1:8010（`AKIOKA_CLOUD_URL=http://127.0.0.1:8019`）
- 対象：発注依頼 6887（元の値 `file_path=/storage/attachments/ZWF7…TP5.pdf`、`file_path_sub=null`）

- `/storage/attachments/…` の旧ファイルは物品システム側の削除対象外（`storage/order_request/` 以外は削除しない仕様）のため、外すだけになる
- ローカルでは `/storage/attachments/…` の実ファイルが無いため、プレビューは404（本番では表示される）

## 検証中に追加で直した点
- 画面のファイルURLで、`/storage/...` のように先頭に `/` があるパスが `//storage` になっていた → 先頭の `/` を除いて連結
- すべて削除したときに `file_path_sub` が `"[]"` で保存されていた → 空なら `null` で保存

## 後片付け
- 6887 を元の値に戻した。発注依頼60も null に戻した（いずれもローカルDB。updated_at は検証時刻に変わっている）

- 検証サーバー 8010／8019 は停止済み
